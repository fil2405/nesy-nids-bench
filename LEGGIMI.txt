LEGGIMI - ricerca degli iperparametri dei modelli neurali su NSL-KDD

COSA FA
Cerca le impostazioni di addestramento (iperparametri) di quattro modelli sul
dataset NSL-KDD. Ogni modello è un "braccio":

  mlp_noweights   rete neurale senza pesi di classe
  mlp_weights     rete neurale con pesi di classe
  ltn_sup         Logic Tensor Network, solo assiomi supervisionati
  ltn_full        Logic Tensor Network, assiomi supervisionati e di dominio

Ogni braccio prova 20 combinazioni, ciascuna su 3 seed, e le giudica sul
validation (una parte del train). Il test non viene mai valutato. I pesi dei
modelli non vengono salvati.

CONTENUTO DELLA CARTELLA
  tune.sh              lo script da lanciare
  LEGGIMI.txt          questo file
  requirements.txt     librerie da installare
  src/nesybench/       il codice
  configs/             le configurazioni
  kb/                  le regole usate da ltn_full
  data/raw/nsl-kdd/    KDDTrain+.txt e KDDTest+.txt

REQUISITI
- Linux, Python 3.11 (provato con questa versione).
- GPU NVIDIA con driver installato. requirements.txt contiene
  tensorflow[and-cuda], che presuppone una GPU NVIDIA: se il server non ce
  l'ha, va detto prima di lanciare. Senza GPU lo script si ferma.
- Accesso a internet per installare le librerie. Git non serve.

INSTALLAZIONE (una volta, dentro questa cartella)
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt

Prima di ogni lancio, in ogni terminale: source .venv/bin/activate

COME SI LANCIA
  bash tune.sh <braccio> [processi]

Esempi:
  bash tune.sh ltn_sup        un processo
  bash tune.sh ltn_sup 2      due processi che si dividono le prove di ltn_sup

Il secondo numero è facoltativo (predefinito 1): quanti processi lavorano su
quel braccio.

I quattro bracci sono indipendenti: si possono lanciare tutti insieme, uno
per terminale. Se si lanciano insieme usano la stessa GPU e la stessa
memoria: se si esaurisce, conviene lanciarne meno alla volta. Lo stesso
braccio non va lanciato due volte insieme (lo script lo rifiuta).

COSA FA LO SCRIPT, IN ORDINE
1. Controllo rapido: librerie, GPU, dati, configurazione. Se qualcosa non va
   si ferma e lo dice, senza avviare il tuning.
2. Tuning. Stampa quante prove sono finite su 20.
3. Riepilogo dei risultati e configurazione migliore.
4. Archivio dei risultati di quel braccio: risultati_<braccio>.tar.gz,
   nella cartella principale.

Se il tuning si interrompe (Ctrl-C, riavvio, errore) basta rilanciare lo
stesso comando: riparte dalle prove non finite.

COSA RIMANDARE
Per ogni braccio, il file risultati_<braccio>.tar.gz (quattro file in tutto).
Contiene i risultati delle prove e i log, non dati né modelli. Se uno script
termina con un errore, crea risultati_<braccio>_incompleto.tar.gz: rimandare
anche quello.

SE QUALCOSA VA STORTO
- Il controllo rapido fallisce: il messaggio dice cosa manca. Il log è in
  logs/tune_<braccio>_check.log.
- Dopo un'interruzione brusca compare un errore su un file .json: cancellare
  quel file in results/tuning/ e rilanciare lo stesso comando.
- Non modificare i file della cartella tra un lancio e l'altro.
